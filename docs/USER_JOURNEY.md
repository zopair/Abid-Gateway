# رحلة المستخدم — Insta Freelancer

> **النطاق:** رحلة تشغيل مستهدفة مقترحة وليست وصفًا لخدمة قائمة. الواجهة الحالية نموذج توضيحي؛ لا تستقبل حوالات ولا تتصل ببنك أو IPN. لا تتحول الخطوات التالية إلى تشغيل فعلي إلا بعد اعتماد البنك الشريك والربط المصرفي والرقابي.

## الأطراف
- **المستقل:** صاحب حساب مصرفي قائم في مصر.
- **العميل الأجنبي/منصة العمل الحر:** الجهة التي تدفع مقابل خدمة أو عمل منجز.
- **البنك الشريك:** البنك الذي يستقبل الحوالة ويصدر أو يدير معرف التحصيل الافتراضي ويجري الفحص والقيد والصرف.
- **البنك الأساسي:** البنك الذي يحتفظ بحساب المستقل بالجنيه المصري.
- **قنوات التحويل والبنوك المراسلة:** أطراف مسار الحوالة الدولية.
- **Insta Freelancer:** طبقة تجربة مستخدم وإشعارات تعرض بيانات موثوقة من البنك بعد التفويض؛ ليست جهة حفظ أموال أو تسوية.

## الرحلة الأساسية خطوة بخطوة

### 0. التسجيل والربط المسبق
1. يختار المستقل تفعيل خدمة تحصيل دخل العمل الحر.
2. يتحقق البنك الشريك من هوية العميل وملف KYC القائم، ويحدد ما إذا كان يحتاج تحديثًا أو مستندات إضافية.
3. يوافق العميل على الشروط ومشاركة البيانات اللازمة وحدود الخدمة والرسوم ومخاطر الصرف.
4. يصدر البنك — إذا وافق على هذا الهيكل — Virtual IBAN/مرجع تحصيل فريدًا مرتبطًا بسجل العميل في أنظمة البنك.
5. يتم التحقق من ملكية الحساب الأساسي وتفويض القيد أو التحويل إليه بالطريقة المعتمدة لدى البنك.

### 1. إرسال الدولار من الخارج
1. يضيف المستقل بيانات التحصيل التي أصدرها البنك إلى ملفه لدى العميل الأجنبي أو منصة العمل الحر.
2. يرسل العميل/المنصة مبلغ USD عبر القنوات الدولية والبنوك المراسلة المتاحة.
3. يجب أن تحمل رسالة الحوالة البيانات المطلوبة لتحديد المستفيد والغرض من الحوالة والمرسل، وأن تكون متوافقة مع قواعد البنك.

### 2. استقبال البنك الشريك والتحقق
1. تصل رسالة الحوالة إلى البنك الشريك أو البنك المراسل وفق المسار المتفق عليه.
2. يطابق البنك مرجع التحصيل/Virtual IBAN مع العميل والحساب المقابل.
3. يفحص البنك المرسل والبنوك الوسيطة والدولة والغرض وقوائم العقوبات ومؤشرات المخاطر.
4. قد يطلب البنك مستندات داعمة مثل فاتورة أو عقد أو إثبات عمل/دفعة منصة.
5. يقرر البنك قبول الحوالة أو تعليقها للمراجعة أو رفضها/إعادتها وفق القواعد.
6. بعد اكتمال الفحص والقيد النهائي، يحدّث البنك حالة المعاملة ورصيد الدولار المتاح. لا تعرض الواجهة الأموال على أنها متاحة قبل تأكيد البنك.

### 3. الإفادة الفورية في Insta Freelancer
1. يرسل البنك إشعارًا موثقًا إلى الواجهة عبر قناة تكامل آمنة.
2. تعرض الواجهة المبلغ والعملة والمرجع وتاريخ القيد والحالة.
3. تظهر الحالات بوضوح: **قيد الوصول / تحت المراجعة / مقيدة ومتاحة / مرفوضة أو معادة**.
4. لا تعرض الواجهة بيانات المرسل الحساسة إلا بالقدر المسموح به.
5. أي إشعار غير نهائي لا يساوي قيدًا مصرفيًا أو ضمانًا بإمكانية التصرف في الأموال.

### 4. طلب تحويل USD إلى EGP
1. يضغط المستقل على «تحويل إلى الجنيه».
2. يطلب النظام من البنك عرض سعر صرف حي وملزم لمدة محددة، مع سعر الوحدة والرسوم وصافي المبلغ.
3. يعرض للمستقل المبلغ بالدولار وسعر الصرف والرسوم والمقابل النهائي بالجنيه ووقت انتهاء العرض.
4. يراجع المستقل التفاصيل ويؤكد صراحة.
5. يتحقق البنك من حالة الأموال وحدود العميل وعدم وجود حظر أو مراجعة معلقة.
6. ينفذ البنك عملية الصرف ويثبت سعر التنفيذ ورقم العملية في سجلاته. إذا انتهت صلاحية السعر، يعاد عرض سعر جديد ولا يتم التنفيذ بالسعر القديم.

### 5. قيد الجنيه والتسوية المحلية
1. يقيد البنك المقابل بالجنيه في الحساب الأساسي المحدد، أو يرسل تحويلًا محليًا إليه وفق نموذج التشغيل المعتمد.
2. إذا كان التحويل بين حسابات بنكية مشاركة ومؤهلًا، يمكن استخدام IPN عبر بنك مشارك وقناة معتمدة.
3. **IPN تنفذ الجزء المحلي من الدفع فقط**؛ ولا تستقبل الحوالة الدولية ولا تنفذ تحويل USD إلى EGP بذاتها.
4. يرسل البنك تأكيدًا نهائيًا بالنتيجة ورقم مرجعي وتوقيت التنفيذ.
5. تعرض الواجهة الرصيد/الحركة بعد التأكيد المصرفي النهائي، مع إيصال قابل للتنزيل أو المشاركة وفق ضوابط الخصوصية.

## مخطط الحالات
Created → Awaiting_Remittance → Received_Pending_Checks → Under_Compliance_Review → Credited_Available → FX_Quote_Issued → Customer_Confirmed → FX_Executed → EGP_Credited → Completed

مسارات بديلة:
- Under_Compliance_Review → Documents_Required → Under_Compliance_Review
- Received_Pending_Checks → Rejected / Returned
- FX_Quote_Issued → Quote_Expired → FX_Quote_Issued
- Customer_Confirmed → Failed / Reversed (وفق قواعد البنك)

## ضوابط تجربة المستخدم
- فصل «وصلت الحوالة» عن «تم قيدها» وعن «أصبحت متاحة».
- عدم إظهار زر التحويل قبل أن يؤكد البنك أن الأموال متاحة للصرف.
- عرض السعر والرسوم وصافي المقابل قبل التأكيد، وعدم تنفيذ تحويل صامت.
- استخدام إشعارات موثقة، مع منع تكرار الإشعار أو تنفيذ الطلب مرتين (Idempotency).
- توفير رقم مرجعي موحد للمتابعة والدعم.
- عرض سبب عام للتعليق دون إفشاء معلومات قد تخل بتحقيق أو بلاغ AML.
- توفير مسار اعتراض وشكوى مع أوقات استجابة واضحة.

## سيناريوهات الاستثناء
| الحالة | سلوك النظام المقترح |
|---|---|
| تأخر الحوالة | تبقى الحالة «بانتظار الوصول»، ولا ينشأ رصيد افتراضي |
| اختلاف اسم المستفيد/المرجع | تعليق للمراجعة والمطابقة اليدوية |
| طلب مستندات | إشعار العميل بقائمة المستندات المطلوبة وقناة رفع آمنة |
| رفض الحوالة | عرض الحالة والإجراء المسموح دون كشف معلومات سرية |
| انتهاء سعر الصرف | إلغاء العرض وإظهار سعر جديد قبل أي تنفيذ |
| فشل IPN أو البنك | عدم إعلان النجاح؛ استعلام حالة العملية ومطابقة القيد قبل إعادة المحاولة |
| تكرار رسالة البنك | تجاهل التكرار باستخدام معرف حدث فريد |
| انقطاع الاتصال | إظهار آخر حالة مؤكدة ووقت تحديثها، لا حالة متفائلة |

## ما يجب إثباته قبل اعتماد الرحلة
- عقد استقبال الحوالة الدولية وملكية/إدارة Virtual IBAN.
- واجهات البنك (API/Webhook) وتوقيع الرسائل وآلية المصادقة.
- اتفاقية سعر الصرف وتوقيت تثبيته والرسوم.
- طريقة القيد إلى الحساب الأساسي، وهل تتم داخليًا أم عبر IPN.
- حدود المعاملات، أوقات التوافر، التسوية، الإلغاء والعكس.
- اختبارات قبول من طرف إلى طرف ببيانات اختبار معتمدة من البنك، لا بيانات حقيقية في بيئة العرض.
